项目状态：开发进度快照，不是正式完成版。

## 原问题与修复

- 原恢复包SHA256和bundle verify通过，但普通独立clone失败；缺失祖先7c04f0d。该问题、原声明、原ZIP及原Release均保留。
- 将三个原分支的相同源码树导入仓库完整父历史之后，形成可正常克隆的源码分支；不宣称补齐了原缺失历史。
- 基线恢复包独立clone、完整fsck及源码树比较已通过。最终功能分支包还须以其冻结提交执行同样验证；结果作为恢复附件发布。
- Windows自动CRLF改变丹炉OBJ字节，导致烘焙场校验失败；用.gitattributes固定OBJ为LF，不修改烘焙哈希、不跳过资源测试。

## 四个失败用例的真实原因

1. 护甲用例装备属性未经历原版更新tick，且generic在原版BYPASSES_ARMOR标签中。本次让装备属性真实生效并改用不绕甲的近战源，断言保留非致命且不消耗遁逃冷却。
2. 旧“灵力不能自动保命”用例使用元婴以上境界，与已确认D29冲突。现在隔离到金丹境界，继续验证仅有灵力不能防止致命伤。
3. 毒附击用例要求免疫中毒的僵尸中毒。现在用可中毒敌人验证正向命中，并明确验证僵尸免疫、宠物/中立/魂仆保护、投射物排除与过期状态。
4. 御剑用例把目标生成在手动推进后的远处非实体可见区块；isAddedToWorld不等于可被碰撞查询。现回到测试区块并断言目标查询可见；同一条命中路径重入验证冷却，墙后保护也要求目标查询可见。

正式御剑控制器的试探性修改已撤回，本轮不修改src/main玩法逻辑，也不改变已确认的融合取舍。
