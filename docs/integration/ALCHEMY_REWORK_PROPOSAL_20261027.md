# 炼丹重塑建议（讨论稿，未实装）

用户已明确：取消草药阶级，仅保留年份；丹药统一1–9品；在现有丹炉UI上改造；环境与多种草药参数融合影响最终品级及真实药效。本轮只制作工作台。

## 数据与计算

- X 建议表示药性向量与环境修正函数；每种草药拥有物种基础向量，不把所有药材压成一个战力数字。Y表示一炉投入的药材种类，当前不将“Y-X”解释为直接减法。
- 环境取样建议从群系、维度、天气、日夜/月相、周围灵气/灵脉获得原始温湿度与灵气值，避免同一因素同时获得群系加分和温湿度重复加分。将来由服务端在明确阶段取样并持久化，不能每帧重掷。
- 年份连续、收益递减；稀有性影响获取和生境，不再称为草药阶级。数量增加批次药量，提纯/浓度决定每颗质量；不能堆大量低龄同种草冲九品。
- 相生、相制、净化、先后投药先转换可用药性池，记录消耗/损失/新药性，不允许循环无限增益。正式规则应配置化、版本化并有反应预算。
- 分别判定类型、品级、效果：主导药性确定类型；多维加权结果与硬性稳定门槛确定1–9品；实际效果使用连续幅度、持续、恢复速度、上限与副作用。
- 丹方建议转为配伍模板/目标区间及学习提示，而非固定物品配方直接指定品级。丹炉/异火建议影响容积、萃取、控温与稳定，不强制保证高品。
- 工作台权重和区间只是可调试起点，正式数值须建立典型配伍、同龄不同草、同草不同龄、环境差异、过量与互斥样本后再定。

## 推荐实现顺序（全部尚未进入游戏）

1. 确认参数名、药性方向、反应规则、九品区间及失败门槛。
2. 为现有全部草药配置基础向量，保留真实年份；删除药阶资格的依赖关系前列出调用入口。
3. 实现独立、确定性的服务端计算器和可解释账本；UI只展示服务器结果。
4. 保存批次投药原始NBT、年份、数量、环境快照、反应和结果，统一预检与扣费；完成前持久化结果，防重放/刷品/重载重掷。
5. 用新的丹药数据版本保存1–9品和连续效果；不新建并行角色账户，不绕过大境界、心境、渡劫资格和属性上限。
6. 保留现有丹药类型的功能定位，逐一设计新参数的映射；旧丹阶、四成色、药阶相关NBT及旧丹方的迁移另列方案，经确认再执行。
7. 在当前丹炉美术基础上替换投药/参数/结果面板，保留可读的简洁主界面，明细折叠；天地为炉随后共用同一计算器。
8. 先做服务端边界/材料守恒/保存重载测试，再做客户端及多人、JEI、光影验收，最后交付游戏包。
