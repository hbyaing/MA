# 磁盘空间维护

恢复验证克隆应放在项目目录外的专用验证目录。验证结束后检查工作区和未跟踪文件，保留验证记录，并将完整副本移入用户指定的 E:/垃圾/日期/任务名；不能只按 build 或 run 的目录名判定其中存档与材料可删除。

清理前记录源路径、文件大小和 SHA-256，移动后逐文件复核。隔离目录可用 NTFS LZX 无损压缩，压缩后再核验内容；同盘移动本身不释放磁盘容量。不得自动清空垃圾目录。

已校验的隔离副本允许按大小及 SHA-256 做硬链接去重，但仅限本次隔离目录，不得链接工作区或运行中的文件。去重后重新校验内容并设为只读。恢复时先复制到新目录，不能直接修改隔离目录中的硬链接；编辑一个链接会影响共享该文件内容的其他路径。按唯一文件标识统计实际占用，避免把硬链接重复计算为空间收益。

保留当前正式 JAR、构建入口、源码、原始素材、必要依赖和唯一恢复资料。无需修改 Mod 时，不为清理而重新构建、启动测试世界或克隆整仓库，避免重新产生大批缓存。不得对运行中的游戏文件、Gradle 锁或其他任务文件作清理。

安装脚本先验证目标实例中的唯一正式包。目标文件名和 SHA-256 都相同时仅更新 reports/last-test-instance-installation.json，不替换文件、不新增备份；版本改变仍按原流程备份并校验。Python 字节码目录不再纳入版本控制。
