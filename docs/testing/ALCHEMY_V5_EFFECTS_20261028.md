# 炼丹V5第07项：连续药效、白名单执行与九品

## 接入和兼容

普通实体炉自由模式的新批次绑定 `alchemy/effects.json` 的 `v5-effects/1` 编译策略，并使用 `furnace-effects-3` 资源表。真实完成反应且通过成丹门槛后，输出单一注册物品 `v5_pill`（复用 UnifiedPillItem / BasePillItem / PillEffects）；其家族由实际效果列表派生，可形成无固定旧丹方的稳定丹或复合灵丹。失败继续为废丹、丹灰或药渣，不能走正常服药入口。

旧05/06批次未绑定EffectPolicy时继续使用原快照与封存结果，不重新评级或转换；旧丹仍保持四成色/五丹阶的原效果和可读性，新V5物品只显示一至九品，不叠加旧枚举。具体旧物品折算仍待12审批，未删除旧ID。固定丹方、天地为炉和辅助入口仍按08统一。网络协议99，两端应同步更新。

## 可审计的编译

可凝结物只取实际生成的 `extract_*` 有效库存，原料标签本身不能执行能力。资源单位合同为mass=potential=1；不满足的策略在开炉预检时拒绝。当前开发参数每颗最小质量40，最多64颗，数量向下取整；未够一颗不补发。每颗先有预算，模块按数据顺序消耗预算及其真实来源的份额，同一来源被多个模块引用时扣同一余额。未知模块、未知字段、重复模块、非法单位、越界参数和脚本拒绝。

策略参数和实际反应完成前的检查点只在服务端保存。编译成功后，有限成丹质量转入已声明的 `v5_bound_pill` 资源，未绑定的材料进入原有residualMass，未绑定药力进入lostPotential；质量、药力和热量三账继续通过原核心校验。编译前ReactionCore保留，PillResult包含family、1–9品、不可变EffectSpec、质量指标、每颗预算与支出、数量、编译/引擎/规则来源版本和哈希；校验时用绑定的策略和ReactionCore重新独立计算并核对。物品只携带公开结果和批次UUID，不携带种子、操作史、原料原始NBT或私有规则全文。

每个模块先按固定设计上限与浓度计算饱和响应，再按纯度/稳定和实际余额裁剪幅度/时长；持续时间和强度共同支付。恢复/灵力/持续恢复/移速具有毫单位连续参数；原版抗性与吸收护盾按其原生级数向下量化，并按实际量化结果计费。没有按九品标签额外乘九倍，也没有按标签数加分。等比扩展有效库存时，每颗效果和品质不因堆量上升，产量在上限内扩展。

## 质量与九品

内部使用固定百万分标尺。纯度为 `1 - 未萃取有效份额/4 - 0.8×毒性份额`；稳定度为 `1 - max(热损伤比, 结构损伤比, 挥发质量比)`；结构完整度由本批结构损伤给出。毒性来自实际毒/幻萃取物，不能抵充有益预算，且作为中毒副作用执行。

功能量取实际已编译能力相对各自固定上限的最大有效比例（持续模块还计入持续比例），不按模块个数累计。评分 `S=clamp(0.48×功能 + 0.28×纯度 + 0.24×稳定 - 0.22×毒性,0,100)`。一至八品依次为[10,20)至[80,90)，九品[90,100]；低于10或无有效能力失败，不强行标一品。

普通硬门槛：纯度/稳定各至少25%，结构至少75%，且有有效功能和完整守恒账。九品另需纯度/稳定各至少95%、结构至少98%、毒性不超过2%、有效功能至少80%及完整账本；不满足九品硬门槛时最多八品。稳定门槛同时限制热损伤/挥发等风险，不能用高分掩盖缺陷。上述数值为可测试开发默认，未宣称最终经济、产量和全量物种平衡已完成。

## 九种实际执行模块

|模块|执行与限制|
|---|---|
|瞬时恢复|固定连续生命量，经原版heal及生命上限结算|
|灵力恢复|复用CultivationLogic.restoreMana，遵守唯一灵力账户与上限|
|持续恢复|固定周期小额恢复；幅度×次数付费，不补发离线脉冲|
|移速修正|原版属性的固定UUID临时修饰符，不能累加成永久属性|
|抗性|有限原版抗性状态，原生级数向下量化|
|护盾|复用原版吸收生命池，不另建血池；已有护盾时不覆盖/补满|
|净化|只清除中毒、虚弱、反胃，不清除心境/渡劫资格|
|修炼|调用既有修炼服务，保留心境、心法和修为上限规则；显示的是基础数值|
|小境界突破|只调用既有advanceMinorStage，不改大境界或跳过原修为/阶段资格|

全部为自身、单目标、零作用范围，不注册命中攻击或递归监听器；元素附着/命中触发/特殊结构等尚无实际模块时严格拒绝，不用词条冒充实现。实际模块最低境界集中经ProgressionGate判断，独立于丹药品级；职业品级、知识、境界、炉阶没有共享ordinal，也不因炼出九品授予称号。原版/既有服务的上限、环境恢复和外部事件仍按原服务结算，不把额外来源归为本丹免费预算。

## 消费、冷却与恢复

BasePillItem保留原服药动画与音效。新V5只有真实服务端进食满14tick才可完成；公开NBT必须与权威PillResult一致，批次必须已交付，且全批已用剂数小于真实产量。拆栈、交易、改名和复制NBT不能扩大全批效果预算；交易后的合法持有人可服用，不要求仍是炉主。创造样本没有权威批次凭证时不能凭空执行药效；真实V5剂量即使创造模式也扣一颗和总预算，旧丹创造行为不变。

共用冷却使用服务端主世界时钟，不能由旧ItemCooldown清理、换手、换栈、重登或死亡重置；同类持续恢复/移速不可无限续叠。原生护盾/抗性记录有限到期时刻，重登扣除已过世界时间，不补盾；外部来源接管同种原生状态后不由本丹清理。死亡移除本丹临时属性与运行状态，重登只恢复尚有效的本丹状态，离线不补发恢复。

消费先写玩家待处理索引与批次DoseIntent，再扣实际物品、执行白名单服务并在同一玩家快照中保存效果、临时状态和消费凭证；读回player.dat确认凭证后才提交DosesUsed并清理意图。恢复先查凭证，已经保存的效果不重复执行；未应用的意图必须仍有实际物品且符合资格。普通情况与交付确认中断有测试；这不是跨文件数据库事务，任意断电/文件系统故障/第三方效果服务异常组合仍归13，异常时保留可诊断记录并阻止重复发奖。
