# 炼丹V5第05项：实体炉批次事务

## 本次接入

普通实体炉的“自由炼制”使用真实V5核心。开炉预检结构、距离、权限、知识、火种、材料及整批炉内灵力；预检失败不扣料。材料完整NBT、输入定义、环境样本、异火与规则固定到服务端批次。默认开发流程21个逻辑秒，开炉10灵力，前18步按炉级燃耗预付，冷却3步不耗燃料；不是第07项最终平衡参数。

最多一只蕴月瓶与药材共用原有八槽；每批最多释放1000单位月华，余量留瓶，来源写入批次。活动和待领取状态均锁定投取、漏斗与一键转移；火种不重复消耗。结构失效暂停，卸载不补算离线时间。拆炉将当前剩余库存封存，剩余预付灵力退回核心载体，不重新生成原料。

产物是 `sealed_alchemy_batch` 封存药液，不可服用；物品只带批次UUID，隐藏核心、原始NBT、种子及规则留在服务端。当前没有能力编译、九品、事故副产物或旧物品迁移。固定丹方和天地为炉仍属legacy，按08统一。网络协议97，客户端和服务端应同时更新。

## 持久化和领取

权威数据在世界目录 `data/alchemy-v5/`，包含批次、炉位置索引、玩家待交付索引。原子文件替换前强制写盘，缺少原子替换支持时报错并保留可诊断状态，不悄悄降级。开炉先写批次与位置意图，再托管物品、保存区块；进度先保存下一检查点再应用，旧区块不能重生成投入物。

领取先保存玩家待交付索引和DELIVERING意图，再向背包空位放入带UUID的凭证，保存玩家并读取player.dat确认凭证，最后记录CLAIMED。重登/重试先查相同UUID；已领取批次不能因旧炉体快照再领取。背包满时保留结果，收取不使用未持久化的光标槽。批次仅限所有者领取和主动封存。

已验证正常保存后的两个真实JVM进程重启、旧区块快照恢复、交付确认中断与重复恢复。未声称完成任意断电、底层文件系统故障或实体掉落期间强杀的全组合验证；这些故障范围和多人/JEI/光影综合验收继续归13。异常记录不自动删除。
