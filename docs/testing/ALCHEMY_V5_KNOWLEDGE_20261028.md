# 第09项：丹方理解、部分约束与实践记录

基于已批准并实装的丹道研析台V2，沿用六页、美术、原生槽位坐标和自绘按钮。网络协议102。此交付是09的基础可玩链路，不代表10反推/谱系、11认证或12全量丹药映射完成。

## 游戏内操作

1. 学习已有金疮、聚灵或清心丹方传承，右键丹道研析台，打开“丹方”。其它旧丹方知识继续保留，不擅自映射未实现药效。
2. 上/下页循环浏览已持有传承的概览、硬约束、建议及概念章节。研习每次只学习此前已满足前置的一层概念：辨药与证据 → 药力守恒 → 配伍；火候概念还需实际结算过一批V5炼制。失败/中止也属于真实经历，不授予成功或认证。
3. 完全理解后消耗纸、墨囊各1，保存带来源与内容版本的未验证模板。同一版本再次点击不扣费。模板最多32份；既有基础鉴定笔记仍单独按原64条上限保存。
4. 鉴定合法样本后，可在丹方页检查其**公开实际药效**是否符合当前模板目标。这只判断结果目标，不证明投料、药龄、配伍、流程和可靠性。
5. “实验”页展示本人真实终态批次的结果、逻辑步数、耗灵、结构损伤与差异摘要，支持翻页。不会从他人成丹导入其私人操作日志。

## 实现与边界

- `data/wuxingxiantu/alchemy/research.json`：受控数据定义；4个概念、3个教学模板，全部绑定现有合法丹方及已注册药效模块。严格拒绝重复字段、非整数版本/门槛、未知模块、未知前置、循环、超预算；不执行表达式或脚本。每个打开的服务端菜单固定本次加载的内容，新菜单才读取资源更新。
- 概念与模板笔记扩展既有 `FormulaKnowledge` 的PlayerPersisted账户；不创建第二职业账户。旧丹方持有状态保留，只有研习才补充符合前置的概念；不自动补齐高阶理论。死亡复制保留理解与笔记，分享丹方不复制理解、笔记或认证。
- 阅读去重按稳定概念ID，记录首次理解的内容哈希。重复、复制、更名、另一本传承、重载数据包或同概念改版不反复给收益；没有知识XP或控火XP奖励。新增实质概念需新的受控节点及前置。
- 模板硬约束当前只有实际目标药效及其最低强度、可选毒性上界。建议字段明确标注未验证药龄/比例/环境，不编造可靠区间、材料替代族或已成功的工序窗口。保存冻结目标、建议、来源、内容版本和`UNVERIFIED`状态，不自动改丹药名称或赋予品级。
- 实践记录扩展世界唯一 `PlayerCrafts` 的alchemy行。V5权威批次文件成功提交后记录终态，含失败；同批次多次READY/DELIVERING/CLAIMED不重复记录。保留前128批用于09展示，达到上限后不再追加；不是11认证总账，不声称永久保全所有历史失败。
- 差异摘要对物品/数量、百年药龄桶、实际操作及结局作摘要；UUID和种子不作为创新依据。记录不产生经验/晋升/控火修正，差异计数也不等于发现或独立样本数。
- 操作端、反应引擎、随机流、能力编译和评级策略未因知识状态改变。未理解模板也不阻止既有合法炉体尝试。旧传承道具既有职业心得机制保持兼容；本项新增研习不调用其奖励入口。
- 服务端重新检查操作者、存活、距离、真实工作台、当前页、实际拥有的传承、概念前置和耗材；不信任客户端可见标志。只同步当前页可见文本与本人摘要，不发送原始投料、种子、私有轨迹或隐藏反应规则。
- 使用正常玩家/世界保存。此项不宣称玩家笔记耗材与独立批次文件之间具备任意断电的跨文件原子事务，也不把NBT往返当作所有多人、旧档、光影与故障矩阵通过；完整验证归13。
