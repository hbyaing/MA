# 炼丹V5第06项：事故与有限副产物

## 接入范围

普通实体炉自由模式的新批次使用冻结的 `furnace-incident-2` 规则和 `incidents` 策略。第05项已有存档未携带IncidentVersion时继续绑定原规则，不追溯替换。固定丹方和天地为炉仍按08统一，能力与九品按07实现。网络协议98，需要客户端和服务端同时更新。

现有按钮位置和皮肤不变：运行中主按钮循环1/4/16/0倍火力；一键放入位置变为“停火封存”；一键清空位置变为“有损泄压”；注灵位置变为“封炉温养/恢复炼制”。所有控制仅限批次所有者、存活非旁观玩家及有效距离，每种控制每五世界tick最多一次，停火与泄压可在同一步组合，先写日志后生效。停火不能撤销已提交事故。未新增全知参数面板或泄露种子。

升火从炉内额外余额支付，不能使用未付的能量。泄压按有限库存逐项移除，计入挥发质量与药力账本；一批多属性时按固定ID顺序有界处理，取整不保证整批恰好损失25%。温养不推进工序，但真实核心继续散热、反应与危险判定（历史最多1024事件/64KB，保留旧规则的更低预算），每秒额外支付灵力和托管月华；断供中止，保留有限药渣。它不是无代价的暂停。

## 事故和环境

热损伤、压力与事故优先级使用原纯核心，压力/设备硬故障炸炉优先于焦化；设备失效记录为追加的DEVICE_FAILURE操作，纯核心可从同一操作史独立重放，不使用未记录的事故布尔值；凝结后结构不合格或没有有效药力归为废丹，不标一品伪装成功。凝结前中止归为未凝药渣，凝结后提前收取归为废丹；焦化/炸炉归为丹灰，副产物是一件带批次UUID及代表质量的有限批料，不按堆量再生成整份材料。丹灰沿用现有PillAshItem，单批最多一件；代表质量不足10000时不能用于肥料。无额外炼丹/研究经验奖励。

储存月华不伪造当前夜晚：只有开炉时确有真实月华输入且投入了储存月华，才绑定持续天象依赖。后续日出、天气/遮挡突变造成断供时，从当前步累计结构衰减并显示方向警兆；白天使用瓶装月华的普通路线不会被错误当成当前满月。温养可用真实库存维持，并持续付费。炉体缺件不会无限免费暂停，加载中的失稳持续衰减，超过阈值产生一次设备失效事故。

区块卸载不补算反应或凭空扣取玩家资源；恢复时若世界时间间隔超过40tick，则中断连续反应窗口，并施加有上限的结构衰减，记录真实间隔。每次恢复最多400损伤，不用墙钟离线时间，不把长时间卸载当无损工艺。

## 炉体与持久化

V5炸炉默认是炉内事故：沿用FurnaceExplosion入口进行一次音效/碎屑反馈并解除成型，不对地形、玩家、队友或旁观者施加新的世界伤害，因此不绕过领地保护。原legacy世界爆炸不在本项改写。当前不提供开启新世界破坏的开关，也不宣称完成13项多人保护/光影验收。

炸炉的设备磨损随权威批次先提交，每次500，上限1000；磨损降低下批热容，完全损坏无法开炉。磨损随炉芯存取与掉落保留。闲置、核心槽空时，原升阶按钮可用4铁锭修复；先保存玩家付款，再提交权威修复并保存区块。真实故障分支沿用05的交付意图、玩家存档确认和CLAIMED记录，不生成第二份正常药液。

Windows短暂文件占用只对同一已强制写盘的临时文件重试原子替换，累计等待上限30ms；仍失败则保留旧检查点并暂停，不降级成非原子覆盖。事故记录和批次不会自动清除。已提交的设备磨损和终态不可因旧活动区块快照恢复而逆转。正常重载和模拟交付中断属于已覆盖范围；任意掉电、文件系统故障和实体落地期间强杀仍按13验收。维修不是跨文件数据库原子事务：极端崩溃可能付款已保存而维修未确认，不能宣称零损失。
