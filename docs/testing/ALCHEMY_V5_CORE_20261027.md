# V5 第03项：纯反应核心与独立规格

基线 origin/main 17247ee，功能分支 codex/alchemy-v5-core-20261027。
版本：engine `alchemy-core/0.1.0`，规则 JSON schema=1，服务端检查点 schema=1，随机算法 `splitmix-fnv-domain/1`。

## 边界

这是制作清单要求的小型纯引擎，不是炉体接入完成。正式 JAR 包含核心，但现有 AlchemyService/炉体/天地为炉尚未调用它，旧丹药和存档不迁移。reference.json 是可执行规格样本，不是全草药默认平衡，更不能把它的 product 当作九品丹药。

参数名称来自资源表。cold/hot 是手算样本的两个资源 ID，内核没有按药名/寒热净值写分支；阴、阳等可另外定义为独立库存。配置可定义资源、质量/势能权重、气体系数、反应、阶段、精确温度/浓度/比例/环境窗口、持续步数、能耗和预算。仅支持受控枚举和整数，未知字段/重复键/分数/非法库存/不守恒/未付费增益拒绝。新增算法仍需可信 Java 模块，不执行配置脚本。

## 独立手算依据

用户规范要求有限资源与守恒；以下规格先固定算式，再断言引擎结果，未由被测程序生成期望值。

每份 cold/hot 质量=1、药性势能=1，mediator/residue 质量=1、势能=0，product 质量=1、势能=1。反应：2 cold + 2 hot + 1 mediator → 3 product + 2 residue。

- 每次质量 5→5，势能 4→3，损耗势能=1。不能把“损耗1”再次当作丢失1质量。
- 初始 cold10/hot8/mediator3，只能反应3次；结果 cold4/hot2/product9/residue6。质量21=21，势能18=15+损耗3。
- 用有能耗的反应把 mediator1→product1，若需要热能2、授权势能1，则热能10→8，绑定热能2、势能增益1；热能不足2不执行。

库存单位 MU；势能 PU；热能 EU。温度是 EU/热容量；浓度是库存/批次固定参考量，比例是资源A/资源B。窗口通过 BigInteger 交叉乘积比较，避免整除把510.1误当510；公开峰值温度为整型显示值，准入使用精确有理数。

参考量不能由玩家网络任意传入；第04项材料适配负责确定实际有效体积/介质基准。第03项本身不能证明堆低龄草不升九品，因为尚无年份/能力/品级算法。

## 执行与持久化

每次 step 是一个逻辑步，不自行读取世界或墙上时间。候选规则按 priority、id 排序，共享剩余库存和能量预算；产物下一步才参与。超出步数、总反应进度或操作历史上限时保存已守恒状态并暂停，不无限循环。本版暂停为停止条件，没有提供玩家恢复接口。

窄窗口样本：双方浓度至少750000ppm，比例980000–1020000ppm，温度490–510，环境湿度40–60，mediator至少200，连续40步，才允许 cold750/hot750/mediator200→product1500/residue200。形成后温度超过511可使结构破坏。数值仅为测试容差；不是最终平衡或完整结构机理。

三本账分别校验质量、势能和热能。冷却、反应绑定能量、操作放气、势能损耗、丹灰及爆炸去向有明确记账。压力使用气体系数×热能/热容量的示例模型；不宣称真实热力学。事故检查保留紧急操作之后、反应前后的最大压力，反应不能掩盖危险峰值。压力事故优先于热损伤；终态再 step 不产生新结算。本版残渣仍在库存中按 destination 标记；尚不生成游戏物品。

每个批次有固定种子，正式控火按独立域和计数器抽样；观测不推进该计数器。保存中含操作序列、阶段、环境事件、持有窗口计数、资源账、规则哈希和随机计数器。读取拒绝未知版本、规则漂移、截断、尾随数据、重复键和不守恒状态。规则哈希绑定规范排序的数据，不允许静默改写旧批次。

**检查点含正式种子，仅供服务端持久化，绝不能用作客户端同步或共享研究日志。** 本项只验证字节编解码与重放，不提供磁盘原子写入、崩溃事务、锁料和领取保证；这些在第05项。
