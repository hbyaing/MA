# V5 第04项：真实输入与药材去品阶

基线 `main 3c571f7`，功能分支 `codex/alchemy-v5-inputs-20261027`。目标仍是 Java17 / Minecraft1.20.1 / Forge47.4.10。此项不接管正式炉体的物品事务，也不执行旧丹药九品迁移。

## 本次用户确认的药材规则

删除药材物种的 `medicinalTierCap/medicinalCap`、药材阶级提示及储物袋阶级分类。全部已注册灵植（包括原生与导入物种）在创造栏各保留一个带模板标记的零年物品；服务端创造取物包在插入/丢出前将副本转换成有实际年份的物品，玩家刻监听作为其它代码插入的兜底。随机一次后移除标记，包括随机结果恰为零年的情况。普通零年繁殖苗不带模板标记，不随机；已持有/已保存年份及其它NBT不重掷。

当前普通物种随机范围为 0–10499 年均匀分布，作为可调开发默认值，并非神话或最终平衡结论。`SpiritPlantDefinition.Builder.years(minimum,randomMaximum)` 允许未来物种声明有来源依据的最低年份；本次不添加神话物种或杜撰神话年份。年份字段安全上限扩为10亿以预留特殊灵根，原有合法年份保留。

野生生成也使用明确年份范围，不再先抽药阶。培养仍保持原生境、成熟度、灵壤/灵气条件和原有一年所需刻数；原环境上限转为2499/4499/6499/8499/10499年的数值，不再叠加物种阶级上限，已超过环境上限的老药材不会降龄。没有重做种植、掉落数量、贴图或物种注册ID。

旧炼丹仍使用原结果体系。旧分阶丹方引药改为检查实际年份500/2500/4500/6500/8500，不受物种品阶限制；旧副药与药浴效果的年份强度换算暂留在明确命名的 `legacyEffectBand`，不进入V5输入，也不作为药材等级展示。这些旧能力在后续统一结算/迁移项替换，不能在第04项擅自转换旧丹药。

储物袋取消按阶拆分条目，同种同其它NBT的草药汇为一项，内部继续保存完整年份多重集，按年份从小到大取出。旧袋数据载入时通过原年份数组逐项合并，数量和来源保持；其它NBT不同的物品继续区分。普通背包仍遵守原版NBT堆叠规则，不能为省槽抹掉不同年份。

## V5输入适配

入口 `alchemy/inputs/AlchemyInputs`：只读取被明确选择的真实物品/数量/年份/处理状态及来源NBT。拒绝非药材、未解析创造模板、超额数量和空批次。适配不扣料，不扫描整包，不授予成品。

`data/wuxingxiantu/alchemy/inputs.json` schema1提供固定每株质量、年份曲线、处理响应、药性权重、物种覆盖、月相响应、雨雪透过率及九种已注册异火的最大输入速率。使用同一严格JSON解码器拒绝重复字段、未知字段、非整数、非法范围、未知药性/物种/异火与无来源的超额活性量。资源重载失败保留上个有效快照和诊断，`InputTrajectory` 持有原快照，不在中途换算。

开发默认每株10000 MU；活性比例对应 `1000 + floor(8000*years/(years+1000))` MU/株，处理后增加500 MU/株，从惰性份额中转移。活性总额按该物种药性权重分配，取整余量回惰性份额。不是把每个标签都赋予一份完整材料；阴/阳、寒及其它轴分别保留。每份物品的所有资源加总严格等于固定质量，参考量由真实株数确定；这只是待平衡的输入基线，不是九品评分。

`AlchemyEnvironment` 仅在已加载炉子区块读取服务器天象、月相、即时高度图遮挡、当地雨雪、雷暴、灵气和生物群系温度。露天在本版定义为采样点位于MOTION_BLOCKING高度以上，液体/树叶/实体遮挡方块也阻断；不等待异步光照。无自然天光的维度不提供夜间月华。当前环境事实与连续输入速率分开，不自动创建材料库存或叠加标签奖励。

`InputTrajectory` 将环境变化按确定顺序生成当前逻辑步事件，再应用受限控制；保存于核心既有操作历史。异火读取真实瓶的ID/等级/八种已吸收精华，既不初始化/改写瓶，也不凭等级制造燃料；控火入口限制同一步总热输入。传入热量须由第05项炉体事务先支付，本项不声称已完成扣费授权。动态投药、实体炉锁料及检查点与物品的原子保存同属第05项。

天亮/改时从观察到的当前步更新；连续窗口中断重新计时，库存不清空，不追溯历史。核心检查点仍是仅限服务器的私有数据，含种子，不能发给客户端。完整材料来源、输入定义哈希及该私有检查点的统一磁盘事务将在第05项绑定。

## 蕴月瓶

注册 `wuxingxiantu:moon_bottle` 方块、单件物品和方块实体，放置后每20个服务器刻按当前条件采集。保存源维度及月相，最多16类来源；本版月华数量单位MU，来源不等于当前真实天象。默认容量24000、单次采集/释放上限1000、转移损耗0，是开发默认常量；美术为代码原生方块模型配原版材质，配方暂为玻璃和黏土，均不声称最终平衡/最终美术。

存量经过严格版本/范围校验；卸载和读档的第一个刻仅建立基线，无离线补发，同刻不重复采集。采集满瓶不增量。单次释放返回已扣除量及来源；两个瓶的数据对象可在有容量/来源预算约束下原子分装混合。掉落表保留 `MoonBottle` 到 `BlockEntityTag`，再放置由方块实体读取。右键显示当前储量和来源数。

本项没有向正式炉UI添加供料槽/供给管线，也没有启用漏斗/网络供料。瓶—炉转移、并发和输出事务在第05项；客户端完整显示、多人、专服重启/真实卸载重载及外部光影在各对应后续验收项，不能用数据对象或NBT往返替代这些验证。
